\begin{abstract}
Hash tables are foundational data structures in transaction indexing systems with high turnover rates, where items are continuously inserted and deleted. While open addressing with Linear Probing is cache-friendly, the accumulation of tombstones degrades lookup latency, especially for unsuccessful queries, necessitating costly periodic table rebuilds. \section{Background and Related Work}
Open addressing with Linear Probing (LP), pioneered by Peterson \cite{peterson}, offers outstanding cache locality due to sequential array scans. However, deletion in open addressing cannot simply reset a slot to empty, as this severs the probe sequence of colliding items. The conventional approach introduces tombstones to mark deleted slots, but accumulated tombstones degrade search performance, particularly for unsuccessful lookups, requiring periodic rebuilding \cite{knuth}.

To avoid tombstones entirely, Knuth \cite{knuth} introduced \textit{Algorithm R}, which scans the subsequent cluster and shifts qualifying elements backward into the vacated slot without rehashing. Alternatively, Sedgewick and Wayne \cite{sedgewick} proposed cluster re-insertion, where items trailing the deletion point are extracted and re-inserted via standard put operations. 

Robin Hood hashing, proposed by Celis et al. \cite{celis}, equalizes probe sequence lengths using the Distance from Initial Bucket (DIB). When inserting a key whose current probe distance exceeds the DIB of the resident key, a swap occurs (``robbing the rich to give to the poor''). This property enables two critical features: (1) \textit{Early exit} during lookups, where a search terminates as soon as the search distance exceeds the slot's DIB, and (2) \textit{Backward-shift deletion}, which shifts elements with positive DIB backward by one position, eliminating tombstones entirely.

\section{Methods}
\subsection{Collision Resolution Implementations}
All hash tables implement a uniform \texttt{HashTable} interface operating on 64-bit keys using Fibonacci hashing $h(k) = (k \cdot \phi) \ggg (64 - p)$ for table capacity $M = 2^p$. We evaluate four primary architectures:
\begin{itemize}
    \item \textbf{Separate Chaining (\texttt{sc})}: Singly-linked list per bucket.
    \item \textbf{Linear Probing Tombstone (\texttt{lp-tomb})}: Parallel primitive arrays (\texttt{long[] keys}, \texttt{int[] values}, \texttt{byte[] state}), tracking tombstones with periodic rebuild threshold $\tau \cdot M$.
    \item \textbf{Linear Probing Backshift (\texttt{lp-backshift})}: In-place cluster shift using Knuth's Algorithm R upon deletion.
    \item \textbf{Robin Hood Hashing (\texttt{rh} \& \texttt{rh-noearly})}: Full Robin Hood table tracking DIB per slot with displacement swaps and backward-shift deletion. The variant \texttt{rh-noearly} ablates the early-exit mechanism to isolate its performance contribution.
\end{itemize}

\subsection{Justification for Knuth Algorithm R in \texttt{lp-backshift}}
Between Knuth Algorithm R \cite{knuth} and Sedgewick's cluster re-insertion \cite{sedgewick}, our study adopts \textbf{Knuth Algorithm R} based on three methodological justifications:
\begin{enumerate}
    \item \textit{Algorithmic Complexity}: Knuth Algorithm R executes in strict $\mathcal{O}(K)$ single-pass time over a cluster of length $K$. In contrast, Sedgewick's re-insertion requires re-hashing and repeated probe loops for each trailing element, leading to worst-case $\mathcal{O}(K^2)$ intra-cluster overhead.
    \item \textit{Memory Bus Traffic \& Cache Locality}: Algorithm R strictly performs in-place element movements only when an item cyclically precedes the hole. Non-qualifying elements remain untouched, drastically minimizing cache line invalidations on modern CPU architectures.
    \item \textit{Theoretical Consistency}: Knuth's exact circular modular invariant $((i \le j) ? (i < r \le j) : (i < r \lor r \le j))$ preserves the canonical linear probing cluster distribution without artificial displacement.
\end{enumerate}

\subsection{RQ3: Mechanism Ablation of Robin Hood Hashing}
To rigorously disentangle the performance advantages of Robin Hood hashing, we empirically decompose the algorithm into its three constitutive primitives under identical churn conditions ($M = 262144, \alpha = 0.50, C \in \{65536, 131072, 262144\}$):
\begin{enumerate}
    \item \textbf{Backward-shift deletion} (\texttt{lp-backshift} vs. \texttt{lp-tomb}): eliminating tombstones entirely without periodic rebuilds.
    \item \textbf{DIB-based displacement swapping} (\texttt{rh-noearly} vs. \texttt{lp-backshift}): equalizing probe sequence lengths to reduce probe variance.
    \item \textbf{Early-exit lookup termination} (\texttt{rh} vs. \texttt{rh-noearly}): terminating unsuccessful searches immediately when the probe distance of the query exceeds the DIB of the resident slot ($DIB_{cur} > DIB_{slot}$).
\end{enumerate}

Our empirical findings (summarized in Table~\ref{tab:rq3_results} and illustrated in Fig.~1--3) reveal several key insights:
\begin{itemize}
    \item \textit{Invariant Preservation via Backward Shift}: In both \texttt{lp-backshift} and \texttt{rh}, backward-shift deletion completely prevents tombstone pollution ($0$ tombstones maintained throughout $C = 262144$ churn cycles). Hit lookup probes remain strictly constant at $\approx 1.50$, matching the theoretical expectation $\frac{1}{2}(1 + \frac{1}{1-\alpha})$ for pristine linear probing.
    \item \textit{Early-Exit Advantage on Unsuccessful Queries}: While DIB swapping alone (\texttt{rh-noearly}) does not alter the mean probe count on hit queries compared to \texttt{lp-backshift}, enabling early exit (\texttt{rh}) cuts the average miss probe count from $2.487$ to $1.745$---a substantial \textbf{29.8\%--30.2\% reduction} in probe operations.
    \item \textit{Variance Reduction and Predictability}: Robin Hood hashing eliminates long lookup tails, bounding maximum probe lengths within $O(\log \log n)$, which translates to predictable real-time tail latencies without GC or rebuild pauses.
\end{itemize}

\section{Conclusion}
This empirical study systematically evaluates collision resolution strategies in open-addressing and chained hash tables under high-churn transactional workloads. By comparing Separate Chaining, Linear Probing with tombstones, Linear Probing with Knuth Algorithm R backshift deletion, and Robin Hood hashing, we provide concrete engineering recommendations:
\begin{itemize}
    \item For static or append-mostly workloads with moderate load factors ($\alpha \le 0.50$), standard Linear Probing remains ideal due to minimal memory overhead and sequential hardware cache prefetching.
    \item For dynamic workloads with continuous deletions, tombstone accumulation rapidly degrades lookup performance unless costly periodic rebuilds are executed. Knuth's Algorithm R (\texttt{lp-backshift}) effectively eliminates tombstones with strict $O(K)$ cluster relocation overhead.
    \item For high-churn transaction indexing where absent/miss queries are frequent (e.g., membership verification and deduplication), Robin Hood hashing with early exit provides the optimal combination of zero tombstones, low variance, and up to $30\%$ fewer probe operations.
\end{itemize}
